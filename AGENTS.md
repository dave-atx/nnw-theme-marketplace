# Repository instructions

Use `uv` for every Python command and keep the project on Python 3.14.

After every change to a Python file, run these commands before doing other
validation:

```sh
uv run ruff check --fix .
uv run ruff format .
uv run ruff check .
uv run ruff format --check .
```

Then run the focused tests affected by the change. Before finishing a Python or
catalog change, run the full unit suite and warning-strict Hugo build:

```sh
uv run python -m unittest discover -s tests -v
hugo --minify --panicOnWarning
```

`data/themes.json` is generated by `uv run build-catalog` and is kept in Git so
offline Hugo and pull-request builds work. `catalog/galleries/*.toml` is human
maintained policy. Never commit `.cache/download-history.json`; CI persists it
through GitHub Actions cache.

Gallery manifests share one TOML format, parsed by `src/marketplace/manifest.py`
and documented for authors in `content/several-themes.md`. Where a file lives
decides what it may do:

- A theme repository's `nnw-marketplace.toml` is untrusted. It is read at the
  latest stable release's tag and may only override `name`, `description`, and
  a repository-relative `screenshot` for themes that release already ships.
  Never let it add themes, name another repository, pin a tag, or supply an
  image URL. An invalid hosted file falls back to default card data with a
  diagnostic; it must never drop the listing.
- `catalog/galleries/*.toml` is reviewed policy. Entries also need `source` and
  `[theme.package]`, may use `https://` screenshot URLs, and every `id` must be
  unique across files. An invalid file aborts the build. Start each file with
  a comment naming the gallery and its homepage, and say why each gallery or
  entry is an exception. Prefer getting a theme listed
  automatically over adding an entry, and remove an entry once its theme
  qualifies on its own.

Keep the format, the author page, and these rules in sync. Don't add a field
until something reads it. A new field needs tests for both locations and a
decision about whether hosted files may use it.

The production site is hosted under a GitHub Pages project path. Generate
internal links with Hugo `relURL` or `absURL`, never a root-relative `/path`.

Treat all GitHub and theme-package fields as untrusted. Do not weaken archive
size, traversal, symlink, required-file, or plist validation without tests and
an explicit reason. The install handoff must select from the generated catalog;
never redirect to an arbitrary query-string URL.

Use the installed `playwright-cli` for browser validation. Check installed
browsers with `playwright-cli install-browser --list`; do not invoke Playwright
through `npx`.
